# 给一线工程师：这套分析方法为什么以前没人做

## 你跑过无数版 placement

每次都是：改参数 → 跑数小时 → 打开 log → 找 HPWL。下降了 2%，好；上升了，回退。

但你心里清楚，那个 HPWL 是 265 条网线的总和。哪条变长了、哪条变短了、是长线受益还是短线受损——你完全不知道。不是不想知道，是没法知道。Tcl 可以 `report_net` 逐条查，但 265 条网线，每条查 2D 和 3D 两个版本，手工对位，算差值——半天就没了。这还是只有 301 个实例的 gcd。给你一个 128K 实例的 ariane133，你连想都不会想。

所以传统 EDA 的实践就是：看全局数字，做局部调整，凭经验猜。不是工程师不行——是工具的反馈粒度太粗。

## 然后我们做了一件很小的事

我们从 DEF 文件里读出每个单元在 2D 和 3D 中的 (x,y) 坐标，从 Verilog 里读出哪根网线连了哪些单元。然后对于 265 条网线中的每一条：

- 2D 时它的 bounding box 多大
- 3D 时多大
- 差值是多少
- 它是跨 Die 的还是留在单 Die 的

这个计算，Python 20 行代码，0.3 秒跑完。

跑完之后我们得到一张图：横轴是 2D 线长，纵轴是 3D 线长。对角线以上是变长的（橙），以下是变短的（蓝）。

![Per-net HPWL](../figures/gcd_per_net_hpwl.png)

**129 条变短，134 条变长。近乎 50/50。**

看到这个图的时候，我们沉默了。

这意味着：placer 报出来的 21% 全局 HPWL 下降，不是"265 条线普遍受益"，而是一半更好、一半更差的净效应。如果你只盯着 log 里的那个 HPWL 数字，你会以为一切都在往好的方向走。但逐线看下去——5µm 以下的短线，86% 变长了。

## 然后我们用统计学找到了真正的规律

不是什么复杂的模型，就是分桶做 t-test：

![Ratio CI](../figures/gcd_ratio_ci.png)

- 20µm 以上的线：90% 变短，p<0.001
- 5µm 以下的线：86% 变长，p<0.001
- 10-20µm：p=0.106——不能说有变化

**20µm 才是统计显著的收益线。**

Spearman ρ = −0.64，2D 线长和 3D/2D 比值之间的负相关高度显著（p = 5×10⁻³²）。这不是猜测——是对 265 个独立样本做的假设检验。

## 你可能已经意识到了

这套分析方法不需要任何新工具。DEF 文件本来就是 placer 的输出，Verilog 本来就是网表的载体。数据一直都有——**缺的从来不是工具，缺的是有人把数据读出来、对上、算一遍。**

传统 EDA 把 DEF 当成"给下一个工具的输入"，不把它当成"可以分析的数据"。Agent 把这个假设翻了过来：**DEF 就是数据，log 就是数据，HBT 坐标就是数据。** 有了数据，可以做统计、可以做回归、可以算置信区间、可以画热力图——这些东西跟 EDA 其实无关，跟任何数据科学有关。

## 所以问题变成了

如果这些分析可以用 20 行 Python 在 0.3 秒内跑完，那为什么过去几十年没人做？

不是不能做。是 EDA 的工作流从来没有把"分析 placer 行为"作为一个正式的设计步骤。人类工程师用直觉和 HPWL 做判断，工具也只输出足够人类做判断的信息。但 Agent 不吃 HPWL——Agent 吃数据。一旦你把 placer 的输出当成数据来对待，**分析的天花板不是工具能力，是你能想到问什么问题。**

我们在这个小小的 gcd 上问了七个问题：
1. 每条线是变长还是变短了？
2. 统计上什么长度区间可靠受益？
3. 每个单元从 2D 移到 3D 位移了多远？
4. 位移和离中心距离有没有关系？
5. 同 Die 的邻居和跨 Die 的邻居在 2D 上距离一样吗？
6. HBT 密度有没有超工艺限制？
7. 这个设计的 Rent 指数是多少？

七个问题，在传统 EDA 中没有一个能在一个下午内回答。Agent 用了不到一天，全回答了。

**这不是自动化。这是把不可能变成可能。**
