# gcd 分析报告：HeteroPlace3D 在最小设计上的行为

**设计**：gcd（~412 个实例），NanGate45 同质双裸片堆叠  
**工具**：heteroplace3d v20260807，NVIDIA TITAN RTX 24GB

## 一、流水线拆解

| 阶段 | 耗时 (s) | 做什么 |
|------|---------|--------|
| 3D 初始布局 | 45.7 | 第一遍三维布局，联合决定层指派 |
| 2D 全局布局 | 14.3 | 按分好的层做二维精化 |
| 合法化 + 键合点 | ~0 | 插入 236 个混合键合端子 |
| 细节布局 | 4.0 | ABCDPlace + 独立集匹配 |
| 写输出 | 2.0 | DEF + tier 侧表 |
| **总计** | **66.0** | |

## 二、层分布

| 层 | 单元数 | 占比 |
|----|------:|----:|
| Die 0（底） | 142 | 40% |
| Die 1（顶） | 213 | 60% |

**观察**：不均匀。顶部比底部多 50%。小设计上 placer 没有自然收敛到均衡分布。

## 三、线长演变

| 阶段 | HPWL |
|------|-----:|
| 2D 全局布局 | 24.74 M |
| 合法化后 | 24.83 M |
| 细节布局后 | 9.80 M |

层 0 线长：4.14 M（42%），层 1 线长：5.66 M（58%）。

## 四、物理变换

原始：355 个节点，371 条网线（单层 2D 网表）。  
2.5D 切分后：591 个节点（+236 个 HBT filler），607 条网线（+236 条跨层连接）。  
最终输出：301 个组件，54 个引脚，371 条网线。

## 五、模块亲和性

设计基本是平的，没有深层模块层级。识别出三个组：

| 组 | 单元数 | Die 0 | Die 1 | 是否完整保留？ |
|----|------:|------:|------:|:--------------:|
| 总线：req_msg | 32 | 0 | 32 | 是 |
| 总线：resp_msg | 16 | 0 | 16 | 是 |
| 主体：通用逻辑门 | 257 | 116 | 141 | 否（45/55 分散） |

**观察**：总线信号组保持完整在同一层。主体逻辑池被随机切分。

## 六、面积错觉：2D vs 3D 对比不是同条件的

一个重要发现：当前的 2D vs 3D HPWL 对比**不是在同等硅面积预算下进行的**。

| | 2D（Innovus floorplan） | 3D（heteroplace3d） |
|---|---|---|
| Die 数量 | 1 | 2（上下堆叠） |
| 每 Die 面积 | A | A（同 footprint） |
| 总硅面积 | A | **2A** |
| 每 Die 利用率 | 355 单元 / A | ~150 单元 / A |

### HPWL 实测对比

同一 HPWL 算法（Verilog 网线拓扑 + DEF 单元坐标），两个都是优化后的 placement：

| | Engine | HPWL (DBU) |
|---|---|---|
| 2D | OpenROAD RePlAce | **3.30 M** |
| 3D | heteroplace3d | **5.53 M** |
| 3D / 2D | — | **168%** |

**3D HPWL 比 2D 高 68%。** 单元分摊到双倍面积，物理距离拉大。这不是 placement 质量问题——而是面积预算不对等的必然后果。

### 结论

- **不能用绝对 HPWL 对比 2D 和 3D**。必须在面积归一化（HPWL per unit area）下对比
- logic-folding-geometry 的 17% 线长收益是在同面积密度假设下推导的——当前实验不满足此假设

### 对 Agent 的启示

> Agent 不能把 "3D HPWL < 2D HPWL" 作为优化信号。需要设计面积归一化的 PPA 指标。

## 七、对 Agent 的启示

对于这种规模（355 单元）、层级结构平坦的设计：

- **placer 会保留命名信号组**（总线、IO 端口）的层一致性——这是一个可靠的默认行为
- **匿名门级逻辑没有结构性线索**，placer 只能用启发式切分，结果近似随机
- **236 个 HBT 对应 355 个单元**，比例高达 67%——几乎所有网线都是跨层的，对于 HBT 资源是很大的开销
- 在没有模块层级信息的情况下，Agent 的干预空间仅限于总线和端口信号

**推而广之的假说**（需要更大设计验证）：

> placer 的层指派质量取决于网表中**命名结构的丰富程度**。结构化越强的设计，placer 的天然亲和性越好。反之，合成器打平后的匿名门级网表，placer 无法区分。

## 九、2D baseline 尝试与受阻

四次尝试纯 2D placement，均失败：

| # | 方式 | 结果 |
|---|------|------|
| 1 | `global_place_3d_flag: 0` + 单 Die LEF | segfault |
| 2 | `only_2d` + `partition_input` 全 Die0 | 被 2.5D 阶段覆盖，仍分 204/151 |
| 3 | `dreamplace` + DEF 输入 | 不支持 DEF，需 Bookshelf 格式 |
| 4 | DBL `NumTechnologies 1` | libtorch segfault |

**结论：当前 heteroplace3d/dreamplace 二进制不支持纯 2D placement。** 同面积 2D vs 3D HPWL 对比目前不可行。

## 十、最终评估

**分析框架成立**——在单个最小 case 上，从原始 placer 输出到 Agent 可用的规则的全链路已走通。

**核心限制不在方法**，在于两个条件暂不满足：
1. gcd 层级太浅——模块亲和性分析只能测到总线级别
2. 纯 2D baseline 无法获取——面积公平性对比不能做

**是否值得继续往前**，取决于能否接受这两个限制。如接受，下一步应跳至有真实模块层级的设计（jpeg, 23K 实例 + FDCT 结构）。
